# Operator checklist

This checklist accompanies the implementation; it does not grant the model authority.

Before a live test, select the dedicated local lab explicitly and verify ownership labels, context, node and enrolled payment identity/template. Confirm a one-replica healthy baseline, Service routing and a valid synthetic order. Use a fresh output directory and retain the predeclared protocol. The fixture harness is trusted operator code and must never be exposed to a model.

Keep dry-run as the default controller mode. For approval mode, inspect the exact typed request, live target and approval binding. Enable autonomous mode only through trusted configuration. Use the dedicated expiring executor token and CA; keep it in the private ignored directory. Do not pass kubeconfig, tokens or approval controls to a model. Run predefined denied-operation probes before a test.

During observation, retain request completions, evidence, decisions and audit history. An abstention, fallback, provider failure, denied proposal or ambiguous write is not a recovery success. No automatic mutation retry is permitted. Do not reset a running/uncertain journal to obtain a passing result.

After observation, verify exact-generation readiness and actual business behavior. Record operator restoration separately from measured recovery. Inspect cleanup and live target identity/count before another episode. Delete locally held trial tokens; server-issued tokens expire independently. Preserve failed records and source hashes.

For a failed or interrupted write, stop new executions. Inspect the live API state, request binding and durable audit with operator credentials. Reconciliation is a manual, auditable decision; no generic retry/override interface exists. Escalate spec/UID drift and unexpected replica counts instead of restoring a different target.

For publication, inspect staged paths and secret scan results. Exclude ignored operator profiles, keys, kubeconfigs and trial token files. Verify the actual repository visibility and destination. Never describe local tests as GitHub CI or an unpushed commit as published. The local audit assumes a trusted OS administrator and is not an external tamper-proof service.
